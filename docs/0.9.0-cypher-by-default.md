# Cypher by default, on every store — 0.9.0

## Breaking: a statement of no language is Cypher on Postgres, Oracle and SQLite

A statement given as a plain string, `QuerySpecification.withStatement("…")`, names no language. Before 0.9.0 it was
Cypher on Neo4j, FalkorDB, Memgraph and Neptune, and SQL on Postgres, Oracle and SQLite, so hand-written Cypher failed
on a SQL store unless it was wrapped in a `CypherStatement`. Drivine is a graph library: from 0.9.0 the same statement
is Cypher on every store, and a SQL store compiles it to its SQL, as it compiles a `CypherStatement`.

| Statement | Graph engines | Postgres, Oracle, SQLite before | Postgres, Oracle, SQLite from 0.9.0 |
|---|---|---|---|
| `withStatement("…")` | Cypher | SQL | Cypher, unless the datasource defaults to SQL |
| `withStatement(cypherStatement("…"))` | Cypher | Cypher | Cypher |
| `withStatement(sqlStatement("…"))` | sent as it is | SQL | SQL |

A datasource can make SQL its default instead, with a new connection property, `defaultLanguage`:

```kotlin
ConnectionProperties(type = DatabaseType.POSTGRES, host = "localhost", databaseName = "app", userName = "app",
    password = "secret", defaultLanguage = QueryLanguage.SQL)
```

```yaml
database:
  datasources:
    graph:
      type: POSTGRES
      default-language: SQL
```

Unset, it is `CYPHER`. `SQL` on a store that runs no SQL, Neo4j, FalkorDB, Memgraph, Neptune or Embabel, is refused as
its provider is built:

```
Datasource 'graph' is NEO4J, which runs Cypher and no SQL, so its defaultLanguage cannot be SQL. Leave defaultLanguage
unset, or set it to CYPHER, and mark a statement that is SQL with sqlStatement(...) on a store that speaks SQL.
```

`QueryLanguage.PLATFORM_DEFAULT`, what a plain string is, stays, and now means the connection's default language:
Cypher, unless the datasource is registered with `defaultLanguage = SQL`.

### Migrating

SQL of your own sent to Postgres, Oracle or SQLite as a plain string is now compiled as Cypher, and fails. Either:

- mark each SQL statement: `withStatement(sqlStatement("SELECT …"))`, or `SqlStatement("…")` from Java; or
- set `defaultLanguage: SQL` on the datasource, and keep its statements as they are. A `cypherStatement(...)` on it is
  still compiled.

A `CypherStatement` written so that a statement ran on every store keeps working, and can now be a plain string. Neo4j
schema DDL given as a plain string to a SQL store (`CREATE INDEX … FOR (n:L) ON (n.p)`) is applied through the schema
manager, as a `CypherStatement` of it was.

`SqlCypherFixtures.over` no longer tells Cypher from SQL by what a statement opens with: every statement goes to the
store as it is, and `MATCH (n) DETACH DELETE n` still empties the graph's tables. A test fixture in SQL is marked with
`sqlStatement(...)`.

The object managers, the schema manager, the store's identity and the store layout migration mark their own SQL, so
nothing else changes for them.
