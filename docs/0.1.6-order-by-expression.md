# Order by an expression over the root's properties — 0.1.6

`orderBy` took property references only. It now also takes an expression built from the root's
properties, arithmetic, a few functions and values the caller binds, so a ranking computed from
several properties stays in the database with its `LIMIT`: a top-k read does not load every
candidate. No existing order changes behaviour. Issue #79; the motivating case is the effective
confidence of embabel/dice#162.

## The DSL

```kotlin
val asOf = Instant.now()

graphObjectManager.loadAll<PropositionView> {
    where { proposition.status eq "active" }
    orderBy {
        case(
            (proposition.validFrom above asOf) or (proposition.validTo atMost asOf) then 0.0,
            otherwise = proposition.confidence * coalesce(proposition.boost, 1.0) *
                exp(-proposition.decay * floor((epochSeconds(asOf) - proposition.lastAccessedSeconds) / 86400)),
        ).desc()
        proposition.id.asc()    // breaks the ties of the score, as after a property
    }
    limit(20)
}
```

The building blocks, all in `org.drivine.query.dsl`:

| Kotlin | Java (`OrderExpressions.*`) | Meaning |
|---|---|---|
| `a + b`, `a - b`, `a * b`, `a / b`, `-a` | `plus`, `minus`, `times`, `div`, `unaryMinus` | arithmetic; an operand is a property reference, an expression, or a number |
| `exp(x)` | `exp` | `e` raised to `x` |
| `floor(x)` | `floor` | the largest whole number no greater than `x` |
| `coalesce(x, y, …)` | `coalesce` | the first that has a value |
| `epochSeconds(property)` | `epochSeconds` | a stored moment as seconds since the epoch, with the fraction |
| `epochSeconds(instant)` | `epochSeconds` | a moment of the caller's as seconds, bound as a number |
| `case(c1 then v1, …, otherwise = v)` | `caseOf(new CaseBranch[]{…}, v)`, `c.then(v).otherwise(w)` | the value of the first branch whose condition holds |
| `a above b`, `below`, `atLeast`, `atMost`, `equalTo`, `notEqualTo` | the same names | comparisons in a case; `b` is an operand or a value, bound |
| `x.hasValue()`, `x.hasNoValue()` | the same names | tests for a value |
| `c and d`, `c or d`, `!c` | `c.and(d)`, `c.or(d)`, `c.not()` | combinations of conditions |
| `param(value)` | `param` | any value, bound |

An expression orders with `asc()` / `desc()` inside an `orderBy` block, which take
`nullsFirst()` / `nullsLast()` after them as a property order does. From Java,
`expression.descending()` gives an `ExpressionOrder` for `JavaQueryBuilder.orderBy`, and a generated
property reference is an operand as it stands:

```java
gom.query(PropositionView.class).filterWith(PropositionViewQueryDsl.class)
    .orderBy(q -> times(q.proposition().confidence(), exp(unaryMinus(q.proposition().decay()))).descending())
    .orderBy(q -> q.proposition().id().ascending())
    .limit(20)
    .loadAll();
```

## What it guarantees

- **Values are bound.** Every value in an expression that is not a property — an `asOf`, a number
  written in the expression — is a parameter (`$_order_0`, … on Cypher; `$_p…` on Oracle). None is
  written into the statement, so its text is the same for every `asOf`.
- **Division is of real numbers** on every backend: Cypher divides two integers as integers, so the
  Cypher form is `toFloat(a) / b`. Division by zero is not the same on each: Oracle refuses the
  statement (`ORA-01476`), and so does Neo4j where the divisor is a whole number; FalkorDB and
  Memgraph run it, and where such a row sorts is theirs to say. Guard a divisor that can be zero
  with a `case`.
- **Ties fall to the next term.** An expression is one term of the `ORDER BY`; the terms after it
  order the rows it ties.
- **A null is not a crash.** A property with no value makes the arithmetic it is in null, as in
  Cypher and SQL; a comparison with no value holds for no row, so such a row takes a case's next
  branch. `coalesce` supplies a default.
- **Only the root's properties.** An expression is one value per root, so a property of a related
  node is refused (`IllegalArgumentException`). On a view the expression reads the root by the keys
  of the view's projection, as a property order does.
- **No seek.** A keyset cursor holds property values; an order by an expression under `seek` is
  refused (`IllegalArgumentException`). Use `skip` / `limit`.
- **No index advice.** No index holds an expression's value, so no index is advised for an order
  that has one.

## Each backend

| | arithmetic, `exp`, `floor`, `coalesce`, case | `epochSeconds(property)` |
|---|---|---|
| Neo4j | yes | `(p.x.epochMillis / 1000.0)` |
| Memgraph | yes | `(timestamp(p.x) / 1000000.0)` |
| FalkorDB | yes | **refused**: FalkorDB holds a moment as its ISO-8601 text and has no function that reads one as a number |
| Oracle | yes, as SQL (`EXP`, `FLOOR`, `COALESCE`, `CASE`) | from the interval since the epoch, for a property a field declares as a moment; refused for any other |

A grammar not in the table refuses `epochSeconds(property)` the same way. A refusal is an
`UnsupportedOrderFunctionException`, naming the function and the engine, thrown while the statement
is built: nothing is sent to the store. On FalkorDB, store the moment's seconds
since the epoch in a property of its own and order by that — the comparisons of a validity window
still work on the moments themselves, since FalkorDB compares their fixed-width text in time order.

On Oracle a property is read as the type of the field that declares it, as an order by it is. A
property no field declares is read as a number in arithmetic, in a comparison as the kind of the
value it is compared with, and as text in `hasValue()` / `hasNoValue()`, so a text counts as a value.

## What changes in the API

`OrderSpec` and the new `ExpressionOrder` are both an `OrderTerm`. `OrderClauseResult.rootOrders` and
`JavaQueryBuilder.orderBy` now carry `OrderTerm` where they carried `OrderSpec`, and
`OrderClauseResult` has the expression's `bindings`. A caller that reads `rootOrders` as property
orders narrows them with `filterIsInstance<OrderSpec>()`.

## `loadAll(class, where)`

The raw `loadAll(class, whereClause)` still takes no order. It has no need to: a store that ranks
moves its read onto the DSL — `where`, `orderBy` with the expression, and `limit` — rather than
keeping a hand-written statement beside it.
