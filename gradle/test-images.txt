# The container images the tests run against, in one place. A test names an image by its moving
# tag, and the tests of every module run it as the image pinned here: see PinnedImages.
# Bump a line deliberately, and run the suite. The pin keeps a run reproducible: an engine's new
# release changes nothing until a line moves, so a pull request's run fails only for its own change.
# Keep each pin at the engine's current release, so a release's breakage shows up soon.
# The nightly workflow, nightly-latest.yml, runs with no pins (FalkorDB's latest comes from ghcr.io,
# see build.gradle's testImagesLatest): when it fails on a new release, fix Drivine for it and move
# the line. See TEST_CONTAINERS.md.
# The library's DrivineTestContainer runs neo4j:latest, which users get unpinned; the suite runs it
# as the pin here. Its image can be overridden with NEO4J_TEST_IMAGE or -Dtest.neo4j.image.
#
