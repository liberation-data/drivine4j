# Java DSL names, and ordering a property-bag fragment — 0.0.87

## Breaking: the Java query DSL has its own method names

Every DSL operator used to exist twice on `PropertyReference`, under one name: a plain member for Java
(`asc(): OrderSpec`, `eq(v): PropertyConditionBuilder`) and a context-parameter member for Kotlin that
registers itself inside `where` / `orderBy` / `seek`. Kotlin 2.2 resolved the tie in favour of the
context one. Kotlin 2.3 does not, so a consumer on 2.3 could not write `orderBy { query.id.asc() }`.

The Kotlin DSL is unchanged. The Java methods are renamed:

| Kotlin | Java, before | Java, from 0.0.87 |
|---|---|---|
| `eq` / `neq` | `eq` / `neq` | `isEqualTo` / `isNotEqualTo` |
| `gt` / `gte` | `gt` / `gte` | `isGreaterThan` / `isAtLeast` |
| `lt` / `lte` | `lt` / `lte` | `isLessThan` / `isAtMost` |
| `isNull` / `isNotNull` | `isNull` / `isNotNull` | `isAbsent` / `isPresent` |
| `contains` / `startsWith` / `endsWith` | same | `hasSubstring` / `hasPrefix` / `hasSuffix` |
| `asc` / `desc` | `asc` / `desc` | `ascending` / `descending` |
| `after` | `after` | `cursorAfter` |

```java
JavaQueryBuilderKt
    .query(graphObjectManager, RaisedAndAssignedIssue.class)
    .filterWith(RaisedAndAssignedIssueQueryDsl.class)
    .where(dsl -> dsl.getIssue().getState().isEqualTo("open"))
    .orderBy(dsl -> dsl.getIssue().getId().descending())
    .loadAll();
```

Kotlin code that built an order spec and registered it by hand, `this(query.issue.id.asc())`, now
writes `this(query.issue.id.ascending())`, or simply `query.issue.id.asc()`.

`OneNamePerLanguageTest` keeps the two sets apart. Drivine itself builds on Kotlin 2.2, where the
compiler still breaks the tie, so the rule is checked by the test rather than the compiler.

## Fixed: ordering a `@PropertyBag` or polymorphic fragment

These fragments return through `WITH properties(n) AS props, labels(n) AS lbls`, which dropped `n`, so
the `ORDER BY n.<field>` after the `RETURN` referred to nothing: every ordered or keyset-paged load of
one failed with `Variable n not defined`, on every engine. The `WITH` now carries `n` through (#20).
