# Node labels as a field, a flat property bag, and runtime-typed relationships — 0.0.91

Three additions for nodes whose labels, properties or relationship types are not known when the
model is written. Nothing existing changes behaviour.

## `@NodeLabels`

A set-valued field on a `@NodeFragment` whose contents are the node's labels, beyond the fragment's
own. Loaded from the node's labels; saved as real labels.

Saving follows `NullPolicy`: `IGNORE` adds the field's labels and removes none; `CLEAR` also removes
the labels that are the field's and are no longer in it.

- `Set<SomeEnum>`: the field's labels are the enum's members. It reads only those. An enum that names
  one of the fragment's own labels is rejected when the model is built.
- `Set<String>`: the field's labels are the ones it has written, recorded on the node in the list
  property `__drivine.labels.<fieldName>`. A default save adds to the record; a `CLEAR` save removes
  what the record holds and the field does not, then sets the record to the field. The record is read
  from the database, so the outcome does not depend on a session snapshot. It reads every label on
  the node.

Under `CLEAR` the labels are written even when the field is unchanged since the last snapshot: the
snapshot records what the object said, not what the node carries.

Limits:

- one `@NodeLabels` field per fragment;
- `saveAll` saves a fragment with one per object, not in an `UNWIND`, because labels are part of the
  statement text;
- on a relationship target in a `@GraphView`, a `Set<String>` field adds under both policies and
  removes under neither.

## `@PropertyBag(flat = true)`

A bag with no prefix. Each entry is stored under its bare key; on load the bag holds every node
property that no declared field and no other bag accounts for. One per fragment. An entry whose key
is a declared field's property, or falls under another bag's prefix, is rejected at save. In the
query DSL, `field(key)` / `predicateOn(key, …)` resolve an undeclared key to itself.

## `GraphObjectManager.edges`

`relate(from, to, type, properties, mode)` joins two stored nodes with a relationship whose type is a
runtime value. `loadRelated(from, type, direction, targetClass)` loads the nodes so joined.

The nodes are named by `NodeRef` (fragment class, id, and any further labels the node must carry)
and are matched, never created. `relate` returns whether both were found. `RelateMode.MERGE` keeps at
most one such relationship and sets its properties; `RelateMode.CREATE` makes another each time.
`loadRelated` returns each related node once on every engine.

## Reserved property names

Property names beginning `__drivine.` belong to Drivine. A flat bag never claims one, and a fragment
that declares a field or a bag prefix beginning with it is rejected when the model is built.

## Code generation

Both generators skip a `@NodeLabels` field (it is not a property) and give a flat bag an empty stored
prefix.
