# Dynamic property predicates + full operator parity in `where { }` — 0.0.69

Maintainer handoff for a runtime-key escape hatch in the type-safe query DSL — `property(path)` and
`predicate(path, operator, value)` — **plus** the operators/conditions needed to express embabel's
entire `PropertyFilter` model (`NOT IN`, regex, case-insensitive, `not { }`, `hasAnyLabel`). Together
they let a consumer translate an arbitrary runtime filter into `where { }` and run filtered search
through the object manager, retiring hand-written filter Cypher. Value binding stays parameterized.

> Scope note: this doc covers the original "Phase A" (dynamic key access) **and** "Phase B" (full
> operator parity) — both shipped under 0.0.69.

```kotlin
import org.drivine.query.dsl.property
import org.drivine.query.dsl.predicate
import org.drivine.query.dsl.query

// infix, ergonomic:
gom.loadMatching<ChunkNode>("graph databases", topK = 20) {
    where { query.property("metadata.source") eq "wiki" }     // → n.`metadata.source` = $param
}

// programmatic, for translating a runtime filter object:
gom.loadAll(ChunkNode::class.java, ChunkNodeQueryDsl.INSTANCE) {
    where { runtimeFilter.leaves.forEach { query.predicate(it.path, it.op, it.value) } }
}
```

This is the primitive that lets a consumer route **filtered** search (`loadMatching { where }` /
`loadNearest { where }`) through the object manager even when filter keys are arbitrary — no new
manager surface, since the filtered overloads already take a `where { }` block.

## The two entry points

Both are extensions on `NodeReference` (the interface every generated `…QueryDsl` implements), so
`query.property(...)` / `query.predicate(...)` work for a bare fragment (alias `n`) and, via
`query.<root>.property(...)`, for a view's root fragment.

- **`fun NodeReference.property(path: String): PropertyReference<Any?>`** — an untyped reference bound
  to the runtime property name. Composes with every **base** operator (`eq`, `neq`, `gt`, `gte`, `lt`,
  `lte`, `in`, `isNull`, `isNotNull`). Returns `PropertyReference<Any?>`, so it does **not** expose the
  string-only operators (`contains` / `startsWith` / `endsWith`) — use `predicate` for those.
- **`context(WhereBuilder<*>) fun NodeReference.predicate(path, operator: ComparisonOperator, value)`**
  — appends one `PropertyCondition` from a `(path, op, value)` triple. Covers the **full**
  `ComparisonOperator` set (incl. `CONTAINS` / `STARTS_WITH` / `ENDS_WITH`). `value` is ignored for
  `IS_NULL` / `IS_NOT_NULL` and should be a `List` for `IN`.

`ComparisonOperator` (public, `org.drivine.query.dsl`): `EQUALS`, `NOT_EQUALS`, `GREATER_THAN`,
`GREATER_THAN_OR_EQUAL`, `LESS_THAN`, `LESS_THAN_OR_EQUAL`, `IN`, `NOT_IN`, `CONTAINS`, `STARTS_WITH`,
`ENDS_WITH`, `MATCHES` (regex `=~`), `CONTAINS_IGNORE_CASE`, `EQUALS_IGNORE_CASE`, `IS_NULL`,
`IS_NOT_NULL`. The two `*_IGNORE_CASE` operators render `toLower(lhs) …` and lower-case the bound value.

Two conditions that aren't property comparisons get their own DSL entry points:

- **`not { … }`** — negates a sub-expression: `NOT (c1 AND c2 …)`. Compose with `anyOf { }` for
  `NOT ( … OR … )`. (`WhereCondition.NotCondition`.)
- **`query.hasAnyLabel("A", "B")`** — matches nodes carrying **any** of the labels:
  `ANY(l IN labels(alias) WHERE l IN $p)`. Contrast `instanceOf<T>()` (all of a type's labels).
  (`WhereCondition.AnyLabelCondition`.)

Ergonomic infix sugar mirrors the new operators for hand-written filters: `notIn`, `matches`,
`containsIgnoreCase`, `eqIgnoreCase` (the last three on `StringPropertyReference`).

## Path resolution & safety

`path` is the **stored property name**. A `@PropertyBag(prefix = "metadata")` entry is stored as a flat
node property literally named `metadata.<key>`, so pass the full dotted name. Rendering (unchanged
`CypherGenerator.renderPropertyPath`, the same path `PropertyBagReference.key()` already uses):

- A path **with a dot** is backtick-quoted: `property("metadata.source")` → `` n.`metadata.source` ``
  (so it's a flat-property read, not Cypher nested-map access).
- A plain path is untouched: `property("owner")` → `n.owner`.
- **Values always bind** as `$param_*` — untrusted values can't inject. The generated param name is
  derived from the raw path (`param_n_metadata_source_0`), and `extractBindings` walks the same order so
  bindings stay aligned.
- **Backtick hardening (new):** a backtick inside a dotted path is doubled (`` a`b `` → `` a``b ``) so a
  runtime-supplied key can't break out of the quotes. Note this hardens the **key**; a caller passing a
  fully attacker-controlled *key* should still prefer keys that are property names or prefixed bag keys
  (a key with no dot is not quoted).

Prefer the generated typed accessors (`query.someField`, `query.metadata.key("k")`) when the key is
known at compile time; reach for `property` / `predicate` only for genuinely dynamic keys.

## Why no new manager surface

The filtered `loadMatching(class, Q, …, spec)` / `loadNearest(class, Q, …, spec)` overloads (0.0.68 /
earlier) already accept a `where { }`. `property` / `predicate` just add new ways to populate that
block, feeding the existing `WhereCondition` → `CypherGenerator` parameterized-rendering pipeline. No
change to the search primitives, builders, or `CypherGenerator` rendering (only the backtick-escape
hardening).

## Consumer impact (`embabel-agent-rag-graph`)

This is the primitive that lets `textSearchWithFilter` / `vectorSearchWithFilter` move onto the object
manager. The consumer writes a small `PropertyFilter` → `where { }` translator (a `when` over the
sealed filter subtypes — embabel has no operator enum, the operator *is* the subtype) and drops
`CypherFilterConverter` + the regex `injectFilterIntoQuery` splicing:

```kotlin
// embabel side — path resolution owns the structural-vs-bagged split it already knows (STRUCTURAL_KEYS):
private fun ChunkNodeQueryDsl.pathFor(key: String) = if (key in ChunkNode.STRUCTURAL_KEYS) key else "metadata.$key"

context(WhereBuilder<*>)
private fun ChunkNodeQueryDsl.apply(f: PropertyFilter) { when (f) {
    is PropertyFilter.Eq                 -> predicate(pathFor(f.key), ComparisonOperator.EQUALS, f.value)
    is PropertyFilter.Ne                 -> predicate(pathFor(f.key), ComparisonOperator.NOT_EQUALS, f.value)
    is PropertyFilter.Gt                 -> predicate(pathFor(f.key), ComparisonOperator.GREATER_THAN, f.value)
    is PropertyFilter.Gte                -> predicate(pathFor(f.key), ComparisonOperator.GREATER_THAN_OR_EQUAL, f.value)
    is PropertyFilter.Lt                 -> predicate(pathFor(f.key), ComparisonOperator.LESS_THAN, f.value)
    is PropertyFilter.Lte                -> predicate(pathFor(f.key), ComparisonOperator.LESS_THAN_OR_EQUAL, f.value)
    is PropertyFilter.In                 -> predicate(pathFor(f.key), ComparisonOperator.IN, f.values)
    is PropertyFilter.Nin                -> predicate(pathFor(f.key), ComparisonOperator.NOT_IN, f.values)
    is PropertyFilter.Contains           -> predicate(pathFor(f.key), ComparisonOperator.CONTAINS, f.value)
    is PropertyFilter.StartsWith         -> predicate(pathFor(f.key), ComparisonOperator.STARTS_WITH, f.value)
    is PropertyFilter.EndsWith           -> predicate(pathFor(f.key), ComparisonOperator.ENDS_WITH, f.value)
    is PropertyFilter.Like               -> predicate(pathFor(f.key), ComparisonOperator.MATCHES, f.pattern)
    is PropertyFilter.ContainsIgnoreCase -> predicate(pathFor(f.key), ComparisonOperator.CONTAINS_IGNORE_CASE, f.value)
    is PropertyFilter.EqIgnoreCase       -> predicate(pathFor(f.key), ComparisonOperator.EQUALS_IGNORE_CASE, f.value)
    is PropertyFilter.And                -> f.filters.forEach { apply(it) }        // AND is implicit
    is PropertyFilter.Or                 -> anyOf { f.filters.forEach { apply(it) } }
    is PropertyFilter.Not                -> not { apply(f.filter) }
    is EntityFilter.HasAnyLabel          -> hasAnyLabel(*f.labels.toTypedArray())
} }
```

**This also fixes a latent bug.** `CypherFilterConverter` renders `chunk.<key>` unquoted, so a bagged
key like `metadata.source` becomes Cypher **nested-map access** (`chunk.metadata.source`), not the flat
`` chunk.`metadata.source` `` property — i.e. metadata filters on bagged keys are **currently broken**;
only promoted top-level fields work. Routing through drivine's `property`/`predicate` corrects it.

With the operators above, `CypherFilterConverter`, `injectFilterIntoQuery`, and the per-dialect filter
Cypher can all be deleted — filtered `textSearchWithFilter` / `vectorSearchWithFilter` run 100% through
`GraphObjectManager`.

### One engine caveat: FalkorDB has no regex

FalkorDB doesn't support the `=~` operator, so `MATCHES` (embabel's `Like`) throws there
("FalkorDB does not currently support =~"). Neo4j and Memgraph are fine. If a consumer must support
`Like` on FalkorDB, keep a fallback for that one operator on that one engine; everything else in the
table works cross-engine.

## Follow-ups

1. **Java-friendly `predicate` / `hasAnyLabel`** — `PropertyConditionBuilder`-returning variants for the
   Java fluent `query(T).filterWith(...).where(...)` path (this bump is Kotlin-context-parameter only;
   the embabel consumer is Kotlin, so it wasn't needed yet).
2. **Model-aware key resolution** — optionally let drivine resolve a *logical* key to its stored path
   from the fragment's `@GraphProperty` / `@PropertyBag` annotations, so a consumer needn't know the bag
   prefix or the structural set. Not required (the consumer already owns `STRUCTURAL_KEYS`), but would
   remove the `pathFor` helper.
3. **A drivine-level guard for unsupported operators** — e.g. surface FalkorDB's regex gap as a typed
   `UnsupportedOperationException` at build time rather than a driver error at execution.
