# `@PropertyBag` — 0.0.50

Maintainer handoff for `@PropertyBag`: persist an open `Map<String, *>` field on a `@NodeFragment`
as **flat, prefixed node properties**, round-tripped on save and load. Verified end-to-end on Neo4j,
FalkorDB, and Memgraph.

```kotlin
@NodeFragment(labels = ["Proposition"])
data class PropositionNode(
    @NodeId val id: String,
    val text: String,
    @PropertyBag val metadata: Map<String, Any?> = emptyMap(),   // -> metadata.<key> properties
)
```

`metadata = {"source": "wiki", "score": 3}` persists as `metadata.source = "wiki"`,
`metadata.score = 3` alongside `id`/`text`. Mirrors Spring Data Neo4j's `@CompositeProperty` (kept as
the alias `@CompositeProperty`). Unlike `@JsonPacked`, entries are real properties — filterable and
indexable.

## Semantics

- **Stored key:** `"${prefix.ifEmpty{fieldName}}${delimiter}${key}"`. `prefix` decouples the graph
  namespace from the field name; `delimiter` defaults to `.`.
- **Value types:** each value must be a storable Neo4j primitive or **homogeneous array** (String,
  Number, Boolean, temporal, or arrays/lists thereof). A non-storable value (nested map, object,
  heterogeneous list) throws `IllegalArgumentException` at save **naming the key** — never emits
  Cypher the driver will reject.
- **Multiple bags per fragment** are supported (each with its own prefix). Overlapping prefixes —
  one a delimiter-prefix of another (`a.` vs `a.b.`) — are rejected at model build, since a stored
  key would otherwise be claimed by two bags on load.
- **Read type asymmetry (documented quirk):** a `Map<String, Any?>` reads back driver-mapped types,
  so an `Int` written returns as `Long`. A typed bag / value converter is a follow-up.
- **Empty / null:** an empty bag writes nothing (and clears stale keys); reads back `emptyMap()`.

## Clear-stale-then-set — and the one limitation

On update, keys removed from the map must disappear from the node. drivine diffs the **session
snapshot**: `removedKeys = oldBag.keys − newBag.keys`, emitted as static
`REMOVE n.`metadata.<key>``. The save statement is a single `MERGE … SET … REMOVE …`.

**Limitation (by design):** stale removal needs the prior state, which only exists for
session-tracked objects (the normal `load → mutate → save` flow). A **detached save** — `new`-ing an
object and saving it without ever loading it — upserts the current keys but cannot know which old
keys to remove (there is no portable "remove all keys under this prefix" in Cypher without dynamic
key removal / APOC). This matches how dirty tracking already treats detached objects. Load before
mutating if you need stale keys cleared.

## Load — `.*` projection + client-side reconstruction

A bag's keys are open, so the declared-field projection can't name them. Bag-bearing fragments are
projected with `.*` (the same portable path polymorphic fragments already use), surfacing every node
property. `TransformPostProcessor.reconstructPropertyBags` then walks the result — root fragment and
each relationship target, recursively through nested views — collecting prefix-matched keys into the
bag's map field before Jackson deserialization, and dropping the flat keys.

*Cost note:* `.*` ships **all** properties back, including any embedding vector on the node. For
vector-heavy fragments loaded in bulk this is overhead; filtering to just the prefixed keys in Cypher
isn't portable (needs dynamic key access / APOC). Acceptable for v1; an opt-in narrow projection is a
possible follow-up.

## Filtering — the `key()` accessor

The generated query DSL emits a `PropertyBagReference` (not a scalar) for a bag field, so individual
keys are filterable:

```kotlin
loadAll<PropositionView> { where { proposition.metadata.key("source") eq "wiki" } }
```
→ `WHERE proposition.`metadata.source` = $p`

`CypherGenerator` backtick-quotes a property segment containing a dot (the stored bag key); plain
fields and relationship aliases are untouched, and the parameter name still derives from the raw
path. Composes on the load path **and** inside `loadNearest { where { } }` (the 0.0.49 filtered
vector path) for free.

## Generated Cypher (per engine — identical; only declared-field handling differs)

```cypher
-- save (update dropping "score")
MERGE (n:Proposition {id: $id})
SET n.text = $text, n.`metadata.source` = $_bag0
REMOVE n.`metadata.score`

-- load (projection)
MATCH (n:Proposition)
RETURN { .*, labels: labels(n) } AS result   -- .* surfaces metadata.* for reconstruction
```

(FalkorDB / Memgraph backtick the same way; `.*` map projection is portable on all three.)

## Code

- `annotation/PropertyBag.kt` — `@PropertyBag` + `@CompositeProperty` alias.
- `model/FragmentField.kt`, `model/PropertyBagModel.kt`, `model/FragmentModel.kt` — detect bags,
  partition them out of `fields` into `propertyBags` (with resolved `storedPrefix`), overlap guard.
- `query/FragmentMergeBuilder.kt` — bag expansion (backtick-quoted SET), clear-stale REMOVE, value
  validation; `previousObject` threaded from the snapshot via `GraphObjectMergeBuilder` /
  `GraphViewMergeBuilder`.
- `query/GraphViewProjectionAssembler.kt`, `query/FragmentQueryBuilder.kt` — bag fragments use `.*`.
- `mapper/TransformPostProcessor.kt` — `reconstructPropertyBags`.
- `query/dsl/PropertyReference.kt` — `PropertyBagReference.key(name)`.
- `query/dsl/CypherGenerator.kt` — `renderPropertyPath` backtick-quoting.
- `drivine4j-codegen/.../QueryDslGenerator.kt` — emits `PropertyBagReference` for bag fields.

## Language support

Works fully from **Kotlin and Java**.

- **Persistence (save / load / clear-stale / validation):** language-agnostic (Jackson + reflection).
  `@PropertyBag` on a private-field Java fragment is recognized and round-trips — covered by
  `JavaPropertyBagTest` and a Java save→load on Neo4j.
- **Typed `key()` DSL accessor:** the Kotlin (KSP) generator emitted it in 0.0.50; the **Java (APT)
  generator emits it as of 0.0.51** (`drivine4j-codegen-java`), so the generated Java DSL exposes
  `node.metadata().key("source")`. Covered by a compile-testing test
  (`PropertyBagCodegenTest`) asserting the generated `…Properties` source. Before 0.0.51, Java
  consumers filtered via the string WHERE form (`"n.`metadata.source` = 'wiki'"`), which still works.

## Follow-ups

1. **Typed bags / value converters** (`Map<String, String>`, custom converters) — v1 is
   `Map<String, Any?>` with driver-mapped reads (the Int→Long asymmetry).
2. **Narrow load projection** — avoid shipping the whole property set (incl. vectors) for bag
   fragments; needs portable filtered-key access.
3. **Detached-save stale clearing** — currently requires session tracking (see limitation above).
4. **Catch-all / overflow mode** (`prefix=""` meaning "every undeclared property → bag") — deferred;
   riskier (must not swallow reserved/internal props).
5. **Annotation-driven index over a bag key** — a user can still
   `RangeIndexSpec("Proposition", "metadata.source")` via `SchemaCatalog` manually.
6. **Refactor** `QueryDslGenerator.generateFragmentPropertiesClass` (now hefty) into focused
   emitters — quality-only, post-landing.
